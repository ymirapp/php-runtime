# Vendor-maintained legacy PHP sources

Ymir consumes complete upstream/vendor source inputs for CVE-2026-109618
and CVE-2026-109619. **Do not maintain a Ymir patch set, cherry-pick a subset
of distro patches, or modify vendor C/header contents to make a build pass.**
If a vendor source cannot meet the Lambda contracts through normal build
and runtime configuration, stop for a platform/support decision.

## PHP-team source snapshots: 7.4, 8.0, 8.1

The [PHP security announcement](https://www.php.net/archive/2026.php) links
these exceptional source-backport branches. Dockerfiles consume full-commit
archives and verify their pinned SHA-256 before extraction:

| 7.4 | [`712e60f9edfd03f0960fc4fc3c2c375f42b90aa2`](https://github.com/php/php-src/commit/712e60f9edfd03f0960fc4fc3c2c375f42b90aa2) | `7.4.34-dev` |
| 8.0 | [`82f8f31b16a035c1b67cc253e79f7cc288f4cc20`](https://github.com/php/php-src/commit/82f8f31b16a035c1b67cc253e79f7cc288f4cc20) | `8.0.30` |
| 8.1 | [`1d7dec178a094e6e75b229ce22754045f8c6070a`](https://github.com/php/php-src/commit/1d7dec178a094e6e75b229ce22754045f8c6070a) | `8.1.34` |

Archive URL: `https://github.com/php/php-src/archive/<full-commit>.tar.gz`.
These are complete vendor trees, not release tarballs with locally applied
patches. Their missing parsers/lexers are generated by the upstream build
using build-only Bison/re2c. Preserve the vendor's real version metadata;
7.4's development banner must not be relabeled as 7.4.33.

During preparation, each downloaded snapshot was compared with `git archive`
of the exact commit, and all three commit signatures verified against
Ilija Tovilo's key, fingerprint `259299AD4C7E1F40DE1302FF115CEA7A713E12E9`.
The key came from GitHub HTTPS, not an independent web-of-trust check.
The archive checksums enforced by Docker are observed pins, not signed
php.net release checksums. GitHub may regenerate compression bytes; a
checksum mismatch must fail closed and be investigated, never auto-accepted.

## PEAR bootstrap for the Git snapshots

The PHP Git snapshots omit the release-bundled PEAR installer. For 7.4,
8.0, and 8.1, the build fetches the unchanged upstream
[`install-pear-nozlib.phar`](https://raw.githubusercontent.com/pear/pearweb_phars/72aa5f771f56aaf826641b21159453f993e44450/install-pear-nozlib.phar)
from PEAR commit `72aa5f771f56aaf826641b21159453f993e44450`, with SHA-256
`a71349da29f1a6e3f0792695b167e582375a93c70c0e9d35e7c4675697c5f039`.
The checksum must pass before the file is placed in the vendor installer's
expected path or executed by normal `make install`. No floating `master`
bootstrap or PHAR copied from an unrelated PHP release is used.

## Complete Sury source packages: 7.2, 7.3

The [Sury PHP repository](https://packages.sury.org/php/) publishes Debian
`3.0 (quilt)` source packages. Its `orig` archives and packaging Git
checkouts are **not already-backported trees**. A build-only Debian stage
uses the format's native `dpkg-source -x` preparation to apply the vendor's
**complete** ordered series, unchanged:

| PHP family | Pinned package revision | Vendor packaging commit | Series |
| --- | --- | --- | ---: |
| 7.2 | `7.2.34-66+0~20261021.122+debian13~1.gbpe0bcd4` | [`e0bcd488d9f8da024d9e1a254113539a846cac6d`](https://salsa.debian.org/php-team/php/-/tree/e0bcd488d9f8da024d9e1a254113539a846cac6d) | 159 |
| 7.3 | `7.3.33-35+0~20261021.144+debian13~1.gbpecf76f` | [`ecf76f6726bee03657a2c608240685732312fe54`](https://salsa.debian.org/php-team/php/-/tree/ecf76f6726bee03657a2c608240685732312fe54) | 139 |

The Dockerfiles pin and verify the complete source file set, including the
`.dsc`, original archive, Debian archive, and the 7.3 upstream signature
file. They do not select patches or substitute pristine-source files.
Generated build preparation follows the vendor's own recipes. Compilation
and final Lambda images remain Amazon Linux 2023; Debian supplies source
preparation tools, not customer runtime binaries.

The package inputs were authenticated on 2026-10-22 through:

1. Sury's `InRelease`, signed by key
   `15058500A0235D97F5D10063B188E2B695BD4743`.
2. Its SHA-256 entry for `main/source/Sources.xz`.
3. The source index's hashes of each package descriptor and archive.

The historical key, signed release, and source index are retained under
`provenance/`. Both `.dsc` files are unsigned; do not claim descriptor
signature verification. The trust anchor came from Sury HTTPS, not an
independent identity check. Retained metadata proves pinned bytes, not
current repository freshness or a vendor support guarantee.

```sh
gpgv --keyring "$PWD/runtime/sources/provenance/sury-keyring.gpg" \
    runtime/sources/provenance/sury-trixie-InRelease
```

Sury's complete source includes Debian defaults for sessions, include/PEAR
paths, and extension/header layout. Preserve Ymir's existing Lambda behavior
with supported build/make settings and runtime INI configuration, not by
removing distro patches. The build stage supplies the vendor's own `shtool`
and maps its aclocal/libtool helper paths to native AL2023 files. The pinned
vendor `phpize` probes missing Debian `dpkg` tools only to choose an aux
pathname; its fallback is mapped to AL2023's actual libtool build-aux
location. The missing-tool diagnostics are not suppressed, no commands are
stubbed, and no vendor script is edited. If future sources require other
`dpkg` behavior, reevaluate the integration rather than faking package data.
None of these build-only helper files enters the final layer.

Optional Sury telemetry is not enabled by the current build flags: do not
define `TELEMETRY_HOST` or import distro binary build flags without a
separate privacy/startup review.

## Verification and release boundary

`runtime/test-image.sh <image> <platform>` checks the actual final image,
including bounded legacy mitigation/lifecycle regressions. Both amd64 and
arm64 must pass; source compilation or unchanged API identifiers alone do
not establish extension or Lambda compatibility. These checks do not prove
comprehensive exploit prevention or coverage of every historical CVE.

The legacy mitigations terminate PHP immediately on OOM (exit 1, bypassing
shutdown callbacks/destructors), disable session upload-progress tracking,
and change some multipart handling. Do not introduce automatic application
retries that could repeat side effects. These remain EOL PHP versions;
backport availability is not resumed upstream support or an SLA.

This work does not authorize merging, releasing, publishing images/layers,
or updating the platform's layer catalog. A later approved rollout needs
zip redeployment or a rebuilt/redeployed container base (including pinned
digests). Existing deployments are not patched retroactively. Preserve
recovery artifacts, but recognize that reverting to unpatched sources or
artifacts restores exposure; prefer a forward fix.
